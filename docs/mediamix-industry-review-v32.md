# 업종별 미디어믹스 검수 및 변경 기록

기준일: 2026-09-07. 기준 소스: Claude v31 (`e05c0e0`). 배포 대상: 기존 GitHub Pages.

## 변경 판단

기존 버전은 캠페인 수동 추가와 브랜드별 자료 선택이 중심이었다. 예산만으로 작성하려면 먼저 업종과 목표, 집행 조건을 저장할 수 있어야 한다. 최신 허브 테마와 계산 엔진은 유지하고 그 위에 업종별 자동 구성 계층을 추가했다.

### 수정한 문제

1. 업종·목표·디바이스 선택 후 유효 자료로 구성하고, 이후 예산 변경만으로 다시 배분한다. 다음 새 계획에도 설정을 기억한다.
2. 자동 구성은 동일 업종·제품·디바이스·전환 정의·기준 월의 자료만 비교한다. 다른 업종의 값으로 조용히 대체하지 않는다.
3. 출처 등급, 기준일 순으로 선택한다. 최근 실적, 과거 실적, 과거 제안, 참고값, 가정을 구분한다. 같은 월의 동질 자료는 항목별 중앙값이며 업종 대표 평균으로 주장하지 않는다.
4. 실제 성과라도 비용의 VAT·수수료 기준이 미확인이면 자동 구성에서 제외한다. `costBasis=media-net` 자료만 자동 적용하며, 원본은 보존한다.
5. 원본 브랜드명·고유 캠페인명·비공개 파일명은 일반 벤치마크 화면 및 자동 생성 제안서에 복사하지 않는다. 비공개 원본과 연결 ID는 로컬 백업에 유지한다.
6. 상품 피드·리타겟팅 모수 미확인 캠페인은 제외한다. 광고주별 브랜드검색 정액 견적은 다른 광고주에게 자동 전용하지 않는다.
7. 예산/기간에 따라 캠페인 수를 제한하고 가중 배분한다. 기본 일 공급가 30,000원, 최대 4개, 순서별 가중치 40/30/20/10은 내부 기획 규칙이며 매체 공시 최소액이나 성과 최적화 결과가 아니다.
8. 수동 행 편집은 자동 재구성을 해제한다. 재구성 시 기존 계획은 보관하며 검토 확인은 해제된다. 행 예산을 표에서 직접 수정해도 포커스가 유지된다.
9. 리포트 파서에서 캠페인의 '리드', '카탈로그'라는 단어 때문에 다른 플랫폼으로 분류되던 오류를 수정했다. 매체 열이 플랫폼 분류의 기준이다.
10. CSV의 따옴표·숫자 쉼표·셀 내 줄바꿈을 처리한다. %가 없는 0.18을 임의로 18%로 바꾸지 않으며, 소수/퍼센트포인트 단위는 명시적으로 선택한다.
11. 반올림된 리포트 CPC·CTR보다 원시 비용·클릭·노출을 우선 역산한다. 비용 VAT 포함 여부와 전환 정의를 선택한 뒤 가져온다.
12. XLSX 입력 양식에 `industry`, `goal`, `costBasis`를 반영하고 브랜드 입력을 선택 사항으로 전환했다. 기존 브랜드만 있는 백업은 읽되 분류 전에는 자동 추천에서 제외한다.
13. 제안서에 자동 배분 기준·제외 내역·산출 제한을 남긴다. CVR/AOV가 없는 전환·매출을 0으로 채우거나 목표 ROAS에서 역산하지 않는다.
14. PDF의 과도한 여백과 불필요한 페이지 분리를 수정했다. 오프라인 ExcelJS 로딩 버전과 서비스워커 캐시 버전도 일치시켰다.

## 검증 범위

- 순수 엔진/추가 계산/업종 자동 구성 회귀 테스트.
- 모든 내장 업종과 다섯 목표 조합: 유한한 계산 결과 또는 명시적인 자료 부재로 처리.
- CPC, CPM, CPV, CPI, SEND, FIXED 여섯 계산 방식. 0/미입력 구분, 정액 선결제, 혼합 전환, VAT·마크업, 정수 예산 합계.
- 30개 허브 경로의 로딩 및 미디어믹스 수정·저장·복원·JSON/XLSX 가져오기·내보내기 브라우저 회귀.
- 업종 선택, 예산 300,000원과 6,000,000원 재구성, VAT 포함 6,600,000원, 수동 수정, 검토 전 제출 차단, 화면에서 리포트 붙여넣기.
- 데스크톱 1440px, 태블릿 768px, 모바일 390px의 페이지 가로 넘침 검사 및 스크린샷.
- 실제 내려받은 XLSX 3개를 LibreOffice로 독립 재계산: 숫자 셀 319개 일치, 엔진 결과 162개 항목 대조. 오류 셀 없음.
- 6모델 혼합안과 업종 자동안 PDF 모두 1페이지로 출력되며 주요 라벨·단위·근거와 제한 사항을 확인.

테스트는 합성 자료와 브라우저 전용 격리 저장소에서 수행한다. 검수 산출물과 원본 광고주 자료는 공개 저장소에 넣지 않는다. 이 기록은 다른 실무 도구의 모든 사업 규칙이나 WCAG 전체 적합성을 보증하지 않는다.

## 운영 한계

- 내장 공통 수치는 2024~2025 과거 참고값이며 최신 실집행 자료로 검증된 업종 통계가 아니다. 실제 CVR·객단가 데이터는 제공하지 않는다.
- 업종별 자료가 없는 네이버·카카오·크리테오·GFA 등은 해당 업종의 검증된 자료를 로컬에 등록해야 자동 구성된다. 상품 자체는 수동 계획과 입력 양식에서 선택할 수 있다.
- 예산만으로 업종·목표·세금 계약·전환 정의를 추론할 수 없다. 최초 설정과 제출 전 출처 확인, 광고주·기간 입력이 필요하다.
- 출처의 '실적'은 계산 근거의 성격이지 향후 성과 보증이 아니다. 6개월 이전 자료는 경고한다. 순도달·중복 제거 전환·플랫폼별 어트리뷰션은 산출하지 않는다.
- 미디어별 고정 일예산·상한·재고·심사·트래킹 설치 상태를 실시간 API로 확인하는 기능은 없다. 기획상 제외 조건과 계정 실제 집행 가능 여부는 구분해야 한다.
- 로컬 저장은 브라우저와 프로필별로 다르다. 팀 공유 서버나 기기 간 자동 동기화 기능은 없다. 백업 JSON으로 이동한다.
- XLSX의 검토 상태는 내보내기 시점 기준이다. 중요한 가정 변경은 브라우저에서 다시 검수·출력한다.

## 재실행

```powershell
node --test tests/mix-engine.test.cjs tests/mix-additions.test.cjs tests/mix-autoplan.test.cjs
node tests/browser.cjs
node tests/mix-auto-browser.cjs
```

브라우저 테스트는 `PLAYWRIGHT_PATH` 또는 설치된 Playwright 및 Chrome이 필요하다. `QA_DIR`로 비공개 검수 폴더를 지정한다. `LIVE_URL`은 격리된 브라우저로 배포본 자동 구성 흐름을 재검증할 때만 사용한다.
